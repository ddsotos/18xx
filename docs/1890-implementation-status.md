# 1890 実装状況

## 評価方法と読み方

この文書は、[要件書](1890-requirements.md) の ID と、`lib/engine/game/g_1890` の現行コードを静的に照合した結果である。

| 表示 | 意味 |
| --- | --- |
| 実装あり | 該当するデータまたは処理がコード上にある。個別のプレイテストは未実施の場合がある。 |
| 部分実装 | 骨格はあるが、ルールとの数値・時期・例外が不足または異なる。 |
| 未実装 | 該当する処理を見つけられない、または必要な会社／データが存在しない。 |
| 要検証 | コードはあるが、fixture がなく正しさをまだ確認できない。 |

## 結論

**通常の 18xx の盤面・株式・運営ラウンドを進める骨格と、近鉄・JR の一部固有処理はあります。** 一方で、本シナリオをルールどおり最後まで遊べる状態ではありません。

特に大きな未完了は、次のとおりです。

1. 本シナリオの初期会社証書11社と規定順、および5小会社の運営体は実装済み。
2. 初期株式ラウンドは1890専用の順序保持Waterfall Auctionを利用する。競売全体の1890統合テストは今後追加する。
3. 列車枚数、開始資金、フェイズ／列車上限がルールと一致しない。
4. 大阪市電、神戸高速、近鉄合併の細則、JR 半額配当などの主要能力が未実装または不完全。
5. 1890 専用の fixture と単体テストがない。

## 4. 品質・検証状況

- `g_1890` 配下の Ruby ファイルは Windows Ruby の `ruby -c` で構文エラーがなかった。
- `spec/lib/engine/game/g_1890` は存在せず、1890 専用 fixture も見つからなかった。
- 実行中コンテナで `require 'engine'` による全ゲーム読込みを試したが 60 秒でタイムアウトした。これは 1890 単独の失敗を示すものではないが、起動後の新規 1890 ゲーム作成テストが必要である。
- TODO は `entities.rb` に 9 か所あり、上記の未実装能力と対応する。

## 5. 推奨実装順

1. **フェイズ遷移を統合テストする**: T-10–T-17 の列車購入による遷移、廃車、D下取りを確認する。定数と会社データは修正済み。
2. **初期 SR の統合テストを増やす**: T-20–T-22。後続入札、全員パス、有馬値下げ、全社売却後の通常SR移行を確認する。
3. **近鉄を fixture で固める**: T-51–T-56。大軌の任意／強制転換、阪鉄・河南・奈良の合併を個別テストする。
4. **会社能力を実装する**: 大阪市電・神高・地下鉄・JR・阪神・阪急を優先する。
5. **実プレイ回帰テストを追加する**: 要件書の受入れシナリオ 1–9 を fixture 化する。
