# 1890 実装状況

## 評価方法と読み方

この文書は、[要件書](1890-requirements.md) の ID と、`lib/engine/game/g_1890` の現行コードを静的に照合した結果である。

| 表示 | 意味 |
| --- | --- |
| 実装あり | 該当するデータまたは処理がコード上にある。個別のプレイテストは未実施の場合がある。 |
| 部分実装 | 骨格はあるが、ルールとの数値・時期・例外が不足または異なる。 |
| 未実装 | 該当する処理を見つけられない、または必要な会社／データが存在しない。 |
| 要検証 | コードはあるが、fixture がなく正しさをまだ確認できない。 |

## 結論

**通常の 18xx の盤面・株式・運営ラウンドを進める骨格に加え、1890固有の初期競売、小会社、後発会社、近鉄、JR、大阪地下鉄、阪急・阪神まわりの主要処理はテスト付きで実装が進んでいます。** 一方で、実盤面経路・実OR全手順・視覚表示まで含めて本シナリオをルールどおり最後まで遊べる状態かは、まだ受入れシナリオで未検証です。

特に大きな未完了は、次のとおりです。

1. 実盤面経路を使った受入れシナリオはまだ不足している。
2. 近鉄合併と特別運営は個別処理をテスト済みだが、実際のOR全手順は未検証。
3. JR半額配当はRoute収入までテスト済みだが、実盤面経路との統合は未検証。
4. 神戸高速は処理と盤面上の特殊閉塞マーカーをテスト済み。より実プレイに近い経路・通過権シナリオは未検証。
5. 盤面・専用タイル全体のPDF照合は未完了。

## 4. 品質・検証状況

- `g_1890` 配下の Ruby ファイルは Windows Ruby の `ruby -c` で構文確認している。
- 1890 専用テストは `spec/lib/engine/game/g_1890/game_spec.rb` に集約している。
- 通常検証は Docker Compose 上で `bundle exec rspec spec/lib/engine/game/g_1890` を実行する。
- 2026-07-16 時点の直近確認では 1890 専用テストは 113 examples, 0 failures。
- Docker 実行後に `sh: 2: Syntax error: "(" unexpected` が表示されることがあるが、RSpec結果自体とは別の終了時出力として扱っている。
- `entities.rb` に残る1890固有TODOコメントはない。

## 5. 推奨実装順

1. **実プレイ回帰テストを追加する**: 要件書の受入れシナリオ 1–9 を fixture 化する。
