# RotLA 詳細設計

[基本方針](../rotla-local-play-plan.md) / 詳細設計の入口

## 位置づけ

基本方針は「何を作るか、どの順に作るか、何を検証するか」を定めていた。
この文書群は、状態の保持先、入力Action、前提条件、状態遷移、失敗時の扱い、
受入テスト、実装チケットまで具体化する。実装コードや動作確認済み手順ではない。

初期完成条件は **4人フル（ロング）、固定マップ、12小会社の能力、6サイクル、Hotseat完走**。
自由マップ、ショート、他人数、マイクロは後続。ソロAIやオンライン運営を追加しない。

## 記述の読み方

- **確認済み**：参照コミットのコードまたは採用PDFで確認した事実。
- **設計決定**：この実装の選択。ルール上の事実と区別する。
- **提案API**：新設予定のクラス・フィールド・メソッド。既存APIとして扱わない。
- **未確定**：必要な証拠と担当作業を記す。実装時の推測で埋めない。

## 今回の詳細化で確定した設計

1. 小会社も株式を持つCorporationとして実装する。
2. 初回列車購入を通常購入から分離し、個人資金の早期投入を禁止する。
3. 自由マップは本ゲーム作成前のウィザードで確定し、初期化途中で盤面を差し替えない。
4. 保存は初期設定＋Action再生。マップの設定をcloneにも引き継ぐ。
5. 同意を必要とするゲーム処理は、UIの確認文だけでなく再生可能な選択として表現する。
6. 列車・タイルの個別枚数が確定するまでは「公式構成で完走した」と判定しない。
