# 株式ラウンド詳細

[設計目次](../README.md) / [状態設計](../architecture/state-and-actions.md)

根拠：採用PDF紙面pp.10〜11。以下の状態名は提案。
最初の対象は4人ロング、275ずつ、12社を3列×4社に配置する。
各列の最前面1社だけを設立候補にする。列の上下表現はUIだけの問題で、内部は先頭が候補の配列に統一する。

## 1. 状態機械

| 状態 | 行為者 | 受け付ける入力 | 遷移 |
|---|---|---|---|
| stock_turn | 通常手番の個人 | 競売開始／売却→購入／pass | 競売、株取引、次の個人へ |
| auction_bidding | 時計回りの競売参加者 | 上乗せ入札／辞退 | 残り1人なら会社選択 |
| auction_select_company | 落札者 | Choose(会社ID) | 通常会社は設立、Adaptiveはホーム選択 |
| auction_select_home | Adaptive落札者 | Choose(都市ID) | 設立確定 |
| stock_trade | 通常手番の個人 | 売却群を確定→任意で1株購入→終了 | 次の個人へ |
| stock_end | 自動 | 売り切れ判定・次SR優先権更新 | OR1へ |

### Adaptiveホーム選択の実装契約

`FoundingAuction`がAdaptiveを設立した後、`round.pending_adaptive_home`に会社を
保持し、後続の`Step::AdaptiveHome`がその間の通常SR行為を遮断する。会社の所有者（初期社長）だけが
`Engine::Action::Choose`で都市IDを選ぶ。都市IDはEngineの`City#id`（タイルIDとtile part index）を使い、
座標をActionへ直接埋め込まない。

RotLAのゲームクラスは`rotla_adaptive_home_cities(corporation)`を実装し、首都と固有会社の都市を
除いた「基本都市」の`Engine::Part::City`配列を返す。このフックがマップ固有の都市分類を担い、Stepは
その配列に対して都市・タイル予約、通常・追加トークンがなく、空きスロットがあることを再検証する。線路やタイル上の既存ルートは
候補から除外しない。選択確定時は未使用の会社トークンを`City#place_token(..., free: true)`で配置し、
会社のホーム座標を更新して`pending_adaptive_home`をクリアする。

固定マップでは`FixedMap`がこのフックを提供する。物理マップcatalogのhex単位`city_type`を使い、
`basic`に分類されたhex上の現在タイルの都市を返すため、設立前の合法なタイルアップグレードでも
preprinted tileの都市番号には依存しない。首都プロジェクト効果による分類変更は未実装である。

競売辞退はその競売から離脱するだけ。通常SRのpassとは別管理する。
全員が通常手番で連続passしたら終了。途中の取引・競売で連続pass数をリセットする。
初回SRに会社が1つも設立されなかった場合の再シャッフル・SR再開は公式例外として実装する。

## 2. 設立競売の契約

保持する提案状態：
`initiator_id, resume_player_id, high_bid, high_bidder_id, passed_bidder_ids, pending_company_id`。

開始時に設立候補があり、所持金が120以上であることを確認する。
初回入札は120以上の5の倍数、上乗せは前の入札を超える5の倍数で、手持ち現金以内。
辞退者の再参加は拒否。入札のたびに現金を動かさず、落札確定時まで支払予定額として扱う。
会社選択待ちの間は他のSR取引を許可しない。

設立確定の順序：

1. 落札者、未払い額、候補会社、必要ならAdaptiveの合法なホームを再検証。
2. フェーズ別候補株価から `max(price <= bid / 2)` を求める。
3. 落札額の全額を個人から会社へ移す。株価×2との差額を銀行へ渡さない。
4. 社長証券40%を落札者へ、残り60%を会社の自己保有にする。
5. 株価列の末尾へトークンを入れ、会社を設立済みにし、ホームを置く。
6. 対象列の次の会社を候補にする。
7. **競売を開始した個人の次**へ通常SR手番を戻す。落札者の次ではない。

例：165で落札→初期株価80、会社165、個人の支出165。
黄色で190落札→初期株価90、会社190。上限株価を超えた入札額も会社に入る。

## 3. 株売買の契約

| 操作 | 支払い元→先 | 主な条件 |
|---|---|---|
| 会社の20%株を購入 | 個人→会社 | 1手番1株、購入後60%以下、同SRに売却した会社でない |
| プール株を購入 | 個人→銀行 | 同上。所有者を正しく変更 |
| 個人の株売却 | 銀行→個人 | 会社の初回運営済み、社長不在にならない、プール50%以下 |
| 社長交代 | 既存株券の交換 | 単純に最高保有者を代入せず、社長証券と普通株の交換も行う |

売却はその手番でまとめて行う。実装が複数SellShares Actionを必要とする場合、
売却フェーズの終了を明示し、購入後に追加売却できないようにする。
同社を複数株売ってもその売却手番では株価1段階下落。
別の通常手番で再び売る場合は再度1段階下落する。
対価は当該売却前の価格で計算し、下落後の価格を途中の株に混ぜない。

同率では既存社長を維持する通常時と、売却で社長を失う時の同率処理を区別する。
証券枚数と株数を混同しない。40%社長証券1枚は2株分。

## 4. 株価列とSR終了

株価列の順番をEngineの市場トークン配列で一元管理する案とする。
全株が個人所有なら1段階上昇し、移動先の列末尾へ入る。
会社自己保有またはプール保有があれば売り切れではない。
次SR優先権は最後の非pass行為に従い、競売発起人/落札者の扱いを公式例とfixtureで照合する。
競売後の通常手番復帰は前節の確定規則で実装する。

## 5. 失敗例とテスト

- 119、122、現金超過、辞退済み再入札は拒否。
- 候補列の奥の会社、設立済み会社、予約されたAdaptiveホームは拒否。
- 140＋70で個人65・会社210・個人60%。
- 140＋120で2社なら個人15・両社40%。
- 小会社のプール保有40%に20%を追加売却する操作は60%になるため拒否。
- 初回SRの売却、購入後の売却、同SRに売った株の再購入を拒否。
- 会社選択待ち/ホーム選択待ちで保存し、ロード後に同じ候補・落札額から再開できる。
- 競売発起人と落札者が違うfixtureで手番の復帰を検証する。
