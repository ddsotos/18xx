# 合併・12社能力・サイクル終了

[設計目次](../README.md)

根拠：採用PDF紙面pp.14〜19、24。Bridging、Adaptive、Overnight、Spaciousがショートから除かれる4社。
以前の基本方針でこの4社にExpansiveを挙げた箇所は訂正する。

## 1. 合併の進行

緑フェーズ以降、OR2の後に合併ラウンド。小会社の株価順に提案またはpassを行う。
相手は未合併の小会社で、双方のhub間に遮断されないルートがあること。
実際に持っている列車の距離ではなく、無限距離の接続を確認する。
Overnightの通過能力は候補生成にも適用する。

| 提案状態 | 入力 | 処理 |
|---|---|---|
| offer | Merge(相手会社ID)／pass | ペアと提案IDを記録 |
| consent | 相手社長のChoose(accept/reject) | 拒否なら無順序ペアを当MRの拒否集合へ |
| choose_major | 新社長のChoose(未使用大会社ID) | 全検証後に合併を適用 |
| excess_trains | 新社長のDiscardTrain | 上限内になるまで整理 |
| advance | 自動 | 消えた小会社を対象から除き、次の提案者へ |

同じ人が両社長の場合は同意待ちを自動化してもよいが、結果を再生可能にする。
相手が異なる場合は「同意済み」ボタンのUIログだけでなく選択Actionを残す。
拒否されたA+BをB+Aとして再提案する操作を拒否する。
再ロード後の古い提案への回答も拒否する。

## 2. 株式交換と資産移管

新社長は合併元の**株数合計**が最多の個人。小会社の40%証券は2株と数える。
同率なら公式の先行会社社長によるタイブレークを適用し、同率候補に関する境界例をfixtureで固定する。
この社長が未使用の大会社を選ぶ。

- 小会社20%1株→大会社10%1株。小会社40%証券→大会社2株分。
- 新社長に大会社20%社長証券、もう一方の旧社長証券は10%2枚へ交換。
- 合併元の個人株は同じ個人へ、プール株はプールへ、自己保有株は新会社の自己保有へ。
- 個人の保有率は各社の保有率合計÷2。40%+60%なら大会社50%。
- 株価は2社の平均を株価トラックの値へ切下げ。1867の計算式は使わない。
- 現金と列車を合算し、hubを大会社のものに置換。
- 同じタイルにhubが重なる場合の無料トークン化と追加トークン配置を紙面p.18に従って処理。
- 固有能力と使用済み状態を引継ぐ。旧会社を閉鎖するとき、移管済み列車を共通close処理で消さない。

適用前に株数、移管先、トークン供給、対象IDを全検証する。
資産移管は1回のcommit相当の処理とし、株だけ交換して現金未移管という保存状態を作らない。
列車超過整理待ちは合併完了後の合法な中間状態として保存可能にする。
合併後はhub所有権の変更に伴う経路キャッシュを無効化する。

## 3. 12社の能力契約

共通して、会社の能力は合併後も大会社で機能する。
会社名で毎回分岐するのではなく、元会社ID付き能力インスタンスを持つ案。
効果のないタイミングではAction候補を出さず、直接Actionも拒否する。

| 能力ID（提案）/会社 | 発動・合法条件 | 効果・保存する状態 |
|---|---|---|
| adaptive / Adaptive | 設立時、空き基本都市。首都・固有都市・他社予約地を除く | 初期社長がホームを選ぶ。選択した都市IDは保存し、合併で選び直さない |
| overnight / Overnight | 路線・敷設到達・合併接続判定。合併後はhub配置到達にも使用 | 完全占有都市を通過できる。通過都市は停車数/収益に入れず、同都市重複訪問は不可 |
| bridging / Bridging | 通常の黄色敷設枠を使用して水上へ。専用在庫が必要 | 橋5枚（直線2、広い曲線2、鋭い曲線1）。upgrade不可。水ヘックス端へ向かう線路の例外も適用 |
| spacious / Spacious | 所有列車上限の計算 | 小会社/大会社の基準に常時+1。所有している有効列車と廃車猶予列車を区別 |
| expansive / Expansive | OR中のhub配置、会社資金40と合法な接続先 | 追加hub1個。未使用で合併したら40の使用コストを維持した大会社hubへ |
| suburban / Suburban | 自社OR中、到達可能な基本都市、自社hubなし、1タイル1個 | 郊外トークン2個。移動不可。該当都市を走る各列車に+10。配置済み都市IDを保存 |
| resourceful / Resourceful | その会社の列車が廃車対象になったとき | 次の追加1回の運行まで保持。その間上限外、売却/∞下取り不可。列車ごとの猶予状態を保存 |
| agricultural / Agricultural | 線路upgradeの後 | 黄色1枚を追加で敷設できる。OR内のupgrade完了と追加敷設消費を保存 |
| tunneling / Tunneling | 山岳ヘックスに敷設、先に費用40を払える | 配置後に銀行から会社へ60。差額だけ払う処理にしない。各配置ごとに処理 |
| eastern_mining / Eastern Mining | 固有ホームタイルのupgrade | 専用upgrade列、既存の辺接続を保持。都市の見た目位置と接続の同一性を分離 |
| northern_port / Northern Port | 固有ホームタイルのupgrade | 専用upgrade列を使用。一般の合法条件を満たせば他社もupgrade可 |
| express / Express | 所有列車がちょうど1台の運行 | その列車の停車数+1。元の列車定義は変更せず実効距離として扱う |

Eastern Miningも一般条件を満たす他社のupgradeを許す。
Suburbanは、既存の郊外トークンのある都市へのhub配置と、その逆の可否が非対称なのでFAQを検証する。
Express＋Resourcefulで「所有1台」に廃車猶予列車を含めるか等、原典で直接確定できない複合ケースは
ルール台帳の未確定事項として分離し、勝手に効果を有利に組み合わせない。

各能力について、正常系、拒否系、合併後、save/load後を検証する。
UIには残り橋枚数・郊外トークン・追加hub費・列車猶予・追加敷設枠などを表示する。

## 4. サイクルと終局

| 完了地点 | 次の処理 |
|---|---|
| SR | 売り切れ/優先権処理→OR1 |
| OR1 | OR2 |
| OR2・緑未到達 | 合併を飛ばしてサイクル末へ |
| OR2・緑以降 | 合併ラウンド→サイクル末へ |
| サイクル末・1〜5 | 輸出→フェーズ/廃車/上限整理→次SR |
| サイクル末・6 | 得点確定。次SRに入らない |
| 破産 | 初期仕様では直ちに終局 |

通常輸出は列車山の先頭1枚。2列車が選ばれたら残り2列車をすべて除去する。
輸出で初めて緑になっても、直前に飛ばしたMRを追加実施しない（紙面p.19）。
最終サイクルでは「次SRへ入る前」の輸出を実行しない解釈で実装する設計案とし、
W01で終局順序の原典照合を受入仕様として確定させる。

得点は個人現金＋保有株数×株価。会社金庫は加算しない。
同点時は経営順が最も早い会社の社長という公式条件を扱い、社長でない同点者を含む境界例は台帳に残す。
通常フルをBank Breakや任意の破産者除外続行と混ぜない。

実装チケット：W06〜W08。テストID：MR-01〜MR-04、PH-01〜PH-03、END-01〜END-02。能力は検証計画の全12能力を参照。
