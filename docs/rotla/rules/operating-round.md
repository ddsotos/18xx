# 運営ラウンド詳細

[設計目次](../README.md) / [株式](stock-round.md)

根拠：採用PDF紙面pp.12〜17。Step名は提案API。

## 1. Step列

| Step | 行為者 | 入力と完了条件 |
|---|---|---|
| LeadoffTrain | 新設会社 | BuyTrainまたはpass。初回ORだけ、最大1台 |
| IssueOrRedeem | 会社 | 1株発行、1株買戻し、passのどれか1回 |
| Track | 会社 | 黄色2枚またはupgrade1枚。能力の追加手番もここで管理 |
| Token | 会社 | 合法な配置またはpass。能力の別タイミングに注意 |
| Route | 会社 | RunRoutes。列車なしなら収益0 |
| Dividend | 会社 | payout/withhold。選べない場合も株価処理を1回実行 |
| BuyTrain | 会社／必要時は社長 | 通常購入、他社取引、強制購入。列車なしでpass不可 |
| EndOperation | 自動 | 初回運営済みの記録、次の会社 |

OR開始時に運営対象と順序を確定する案とし、運営済みIDを確認する。
OR中の株価変動で対象を再追加しない。OR2ではその時点の株価で順番を作り直す。

## 2. 先行購入と通常購入を分離する

| 条件 | LeadoffTrain | BuyTrain |
|---|---|---|
| 利用時点 | 新設小会社の初回OR冒頭 | 配当後 |
| 列車山・銀行プール | 定価、会社現金以内 | 定価、必要時は強制購入 |
| 他社列車 | 不可 | 双方合意、最低1、会社現金で支払う |
| 個人負担 | 不可 | 列車なしで不足する強制購入だけ |
| そのORで運行 | 可 | 次のORから |
| 買わない選択 | 可 | 列車なしなら不可 |

既存Train mixinの `president_may_contribute?`、`buyable_trains`、
`buy_train_action` は先行購入には広すぎる可能性がある。
専用Stepで候補を絞るだけでなく、実行時も購入元、定価、所有数、会社現金を再検証する。
先行購入の完了で通常購入Stepまでpass済みにしない。

## 3. 発行・買戻し

会社が保持する普通株1株をプールへ出して、現在株価を銀行から会社に受け取り、
株価を1段階下げる。発行後にプール上限を超える場合は拒否。
買戻しは会社→銀行に現在株価を払い1株を自己保有に戻す。株価は変えない。
同ORに発行と買戻しの両方を行うことはできない。

株価70の会社：140−2列車100＋発行70=110。
建設費・配当由来の会社収入を除けば、追加2列車100を買って10残る。

## 4. 敷設・ルート

基本は黄色2枚またはupgrade1枚。地形コストは配置ごとに支払う。
所有トークンから到達可能な敷設、既存線路の保持、色/ラベルのupgrade制約、
物理タイル在庫を検証する。ルート接続と敷設到達のルールを同じ真偽値で代用しない。

ルートは自社hubを含み、同じ都市・遠隔地を同一路線で二度数えない。
別列車同士で同じ線路区間を共用しない。
ローカル運行はホーム都市だけの1停車を許し、複数列車が同じ都市でローカル運行してよい。
これは既存ルートUIが1停車を送信できるかも含めた実装スパイクを要する。

Bridging、Overnight、Express等の差分は[能力表](mergers-and-abilities.md)を参照。

## 5. 配当と株価

小会社の1株は総配当の20%、大会社は10%。自己保有株にも配当する。
既存Step::Dividendの `payout_per_share`、`corporation_dividends`、
`share_price_change` を接続候補とする。一般会社の10%前提を暗黙に使わない。

| 総配当Dと現在株価P | 株価 |
|---|---|
| D=0 または全額留保 | 1段階下落 |
| 0<D<P | 据置、列の末尾へ移動 |
| P<=D<2P | 1段階上昇 |
| 2P<=D | 2段階上昇 |

比較するのは総配当額であり、社長が受け取る金額ではない。
自己株発行後なら下落後の株価を使う。
株価0に達した会社は解散し、その後の列車購入を続行しない。

例：40配当、社長40%、自己保有60%なら社長16・会社24。
会社→個人の資金移動ではなく、ルールの銀行から各保有者への配当として処理する。

## 6. 強制列車購入の状態分岐

1. 列車を1台以上保有していれば追加購入は任意。個人補填不可。
2. 列車なしでも会社現金で合法な他社取引を成立させれば終了できる。
3. 成立しなければ列車山/銀行プールの最安購入候補を確定する。
4. 会社現金を優先し、不足額だけ社長現金を使う。
5. 足りなければ合法な社長株売却を1株ずつ行い、足りるまで続ける。
6. それでも不足する場合に破産。新しい融資・自動株発行は追加しない。

購入待ちと社長売却待ちをround_stateに保持し、売却対象会社の下落を
強制購入に関する一連の売却ごと同社1回にまとめる（通常SRと別文脈）。
社長証券の保有/交換、プール上限、活動会社の社長交代禁止を個別検証する。
人間の他社取引の可能性を無視して、画面表示前に自動破産させない。

最安の判定は列車名ではなく、その時点の合法な購入候補。
7/∞等の選択・下取りと強制購入の組合せは原典照合をW01/W05で完了させる。

## 7. 会話の具体例をテストへ

140と120で設立→個人15。
先行70会社が40配当→個人31。
後手60会社が発行→会社180。
最安列車が3=200なら、通常購入時に社長が20負担→個人11、会社0、3列車1台。
後手会社は初回運行収益0であり、購入を冒頭へ巻き戻さない。
発行と収益0による2回の株価下落も記録する。

成立条件は先行配当、列車在庫、敷設費等で変わる。
戦略の有利不利をテスト成功条件にしない。

実装チケット：W05。テストID：OR-01〜OR-09、EBUY-01〜EBUY-04。
